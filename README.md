# 미션2 — 나만의 퀴즈 게임

터미널에서 동작하는 파이썬 콘솔 퀴즈 게임입니다.
Python 기본 문법 + 클래스(객체 지향) + JSON 파일 저장으로 만들었고,
**프로그램을 껐다 켜도 추가한 퀴즈와 최고 점수가 그대로 유지**됩니다.

- **저장소**: https://github.com/Quartz13177/mission2
- 외부 라이브러리 없이 **표준 라이브러리만** 사용 (`json`, `os`, `random`, `datetime`)

---

## 1) 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 무엇 | 콘솔 퀴즈 게임 (풀기 / 추가 / 목록 / 점수 / 삭제) |
| 언어 | Python 3.12 (과제 조건: 3.10 이상) |
| 저장 | 프로젝트 루트의 `state.json` (UTF-8) |
| 구조 | 클래스 3개 (`Quiz`, `Storage`, `QuizGame`) + 기능별 모듈 분리 |
| 특징 | 잘못된 입력 · `Ctrl+C` · 파일 손상 상황에서도 프로그램이 죽지 않는다 |

## 2) 퀴즈 주제와 선정 이유

**주제: 개발 입문 기초 상식** (터미널 · Docker · Git · Python · AI 연산)

입학연수 미션1~3에서 **직접 손으로 실습해 확인한 개념만** 문제로 만들었습니다.

| 문제 | 미션1에서 직접 확인한 장면 |
|---|---|
| 컨테이너 설계도 역할은? → 이미지 | `docker images` 와 `docker ps` 의 차이 |
| 현재 위치 확인 명령어는? → `pwd` | 터미널 실습에서 가장 먼저 친 명령 |
| 권한 755에서 소유자 권한은? → 읽기+쓰기+실행 | `permission denied` → `chmod 755` → 실행 성공 |
| 컨테이너 삭제 후 데이터를 남기려면? → 볼륨 | 볼륨은 유지 / 컨테이너 내부는 소실되는 대조 실험 |
| localhost:8080 접속을 가능하게 하는 것은? → 포트 매핑 | `-p 8080:80` 으로 브라우저 접속 확인 |

**선정 이유**

1. 정답의 근거를 **제가 직접 설명할 수 있는** 문제들입니다. 남의 상식 퀴즈가 아닙니다.
2. 같은 과정을 듣는 동료에게 **그대로 복습 도구**로 건넬 수 있어 프로그램의 쓸모가 분명합니다.
3. 미션1~3을 관통하는 개념을 문제로 정리하면서 스스로 복습이 되었습니다.

## 4) 기능 목록

| 번호 | 기능 | 설명 |
|---|---|---|
| 1 | **퀴즈 풀기** | 풀 문제 수를 정하고 출제 → 정답/오답 즉시 안내 → 결과 점수 표시. `h` 입력 시 힌트(−5점) |
| 2 | **퀴즈 추가** | 문제·선택지 4개·정답 번호·힌트를 입력받아 등록하고 즉시 저장 |
| 3 | **퀴즈 목록** | 등록된 문제 목록 표시 (정답은 감춤, 힌트 보유 문제는 💡 표시) |
| 4 | **점수 확인** | 최고 점수와 상세(N문제 중 M개 정답), 최근 5회 기록 |
| 5 | **퀴즈 삭제** | 번호를 선택해 삭제 (삭제 전 y/n 확인) |
| 6 | **종료** | 저장 후 종료 |

### 점수 계산식

```
점수 = round(100 × 맞힌 개수 ÷ 푼 문제 수) − (힌트 사용 횟수 × 5)      # 최소 0점
```

예) 2문제 중 1문제 정답 → `round(100 × 1 ÷ 2)` = **50점**

### 입력 / 예외 처리 (요구사항 3)

| 상황 | 프로그램 동작 |
|---|---|
| 앞뒤 공백 (`" 1 "`) | `strip()` 으로 제거 후 정상 처리 |
| 숫자 아님 (`abc`) | `⚠️ 숫자만 입력할 수 있습니다.` 안내 후 **재입력** |
| 범위 밖 (`9`, `0`) | `⚠️ 1~6 범위의 숫자를 입력하세요.` 안내 후 **재입력** |
| 빈 입력 (Enter) | `⚠️ 입력이 비어 있습니다.` 안내 후 **재입력** |
| `Ctrl+C` (KeyboardInterrupt) | 안내 메시지 → **저장** → 정상 종료 |
| 입력 스트림 종료 (EOFError) | 위와 동일하게 처리 |
| `state.json` 없음 | 기본 퀴즈 8개로 시작 |
| `state.json` 손상 | 손상 파일을 `state.json.bak` 으로 옮기고 기본 퀴즈로 복구 |
| 일부 퀴즈 데이터만 깨짐 | 깨진 항목만 건너뛰고 나머지는 정상 로드 (건너뛴 개수 안내) |
| 퀴즈 0개일 때 풀기/목록/삭제 | "등록된 퀴즈가 없습니다" 안내 후 메뉴 복귀 |

실제 동작 확인:

```
선택: 9      →  ⚠️  1~6 범위의 숫자를 입력하세요. (입력값: 9)
선택: abc    →  ⚠️  숫자만 입력할 수 있습니다. 1~6 사이의 숫자를 입력하세요.
선택: (Enter) →  ⚠️  입력이 비어 있습니다. 1~6 사이의 숫자를 입력하세요.
```

```
# state.json 을 일부러 손상시킨 뒤 실행
📂 데이터 파일이 손상되어 기본 퀴즈로 복구했습니다. (손상 파일: state.json.bak)
   → 퀴즈 8개로 정상 실행됨
```

## 5) 파일 구조

```
mission2/
├── main.py            # 시작 파일 — 게임 객체를 만들고 실행만 한다
├── game.py            # QuizGame 클래스 — 메뉴 진행, 점수 관리, 저장 요청 (사회자)
├── play.py            # 퀴즈 출제 진행 (별도 브랜치에서 개발 후 병합)
├── quiz.py            # Quiz 클래스 — 문제 한 개 (문제/선택지/정답/힌트)
├── storage.py         # Storage 클래스 — state.json 저장·불러오기 (창고 관리인)
├── ui.py              # 입력 검증 / 출력 도우미 함수
├── config.py          # 설정 값 (파일 경로, 선택지 수, 랜덤 여부, 힌트 감점)
├── default_data.py    # 기본 퀴즈 8개 (첫 실행용)
├── .gitignore         # state.json / 파이썬 캐시 제외
├── state.json         # ⚙️ 실행하면 자동 생성되는 데이터 파일 (git 추적 제외)
└── README.md          # 본 문서
```

### 클래스 3개의 역할 분담

| 클래스 | 파일 | 비유 | 담당 |
|---|---|---|---|
| `Quiz` | `quiz.py` | 문제 카드 1장 | 문제·선택지·정답을 갖고 스스로 채점 |
| `Storage` | `storage.py` | 창고 관리인 | `state.json` 읽기·쓰기, 파일 문제 상황 복구 |
| `QuizGame` | `game.py` | 사회자 | 메뉴 진행, 점수 계산, 최고 점수 갱신, 저장 요청 |

**왜 나눴는가**: 저장 방식을 파일에서 데이터베이스로 바꾸고 싶다면 `storage.py` 만 고치면 됩니다.
게임 로직과 문제 데이터는 손댈 필요가 없습니다. 이것이 요구사항의 "기능별 분리"가 필요한 이유입니다.

### 모듈 의존 관계

```
config.py  ← 모든 파일이 참조하는 설정
   ↑
quiz.py  ←  default_data.py
   ↑            ↑
storage.py  ────┘
   ↑
game.py  ←  play.py  ←  ui.py
   ↑
main.py
```

## 6) 데이터 파일 설명 (`state.json`)

| 항목 | 내용 |
|---|---|
| **경로** | 프로젝트 루트 `./state.json` |
| **역할** | 퀴즈 목록 + 최고 점수 + 게임 기록 보관 → 프로그램을 껐다 켜도 유지 |
| **인코딩** | UTF-8 (`ensure_ascii=False` 로 저장하므로 한글이 그대로 보인다) |
| **생성 시점** | 첫 실행 후 최초 저장 시 자동 생성 |
| **git 추적** | `.gitignore` 로 제외 (사람마다 내용이 달라지는 개인 데이터이므로) |
| **안전 저장** | `state.json.tmp` 에 먼저 쓰고 마지막에 이름을 바꿔치기 → 저장 중 중단되어도 기존 파일이 깨지지 않음 |

### 스키마

```json
{
  "quizzes": [
    {
      "question": "Docker에서 '컨테이너를 만들기 위한 설계도' 역할을 하는 것은?",
      "choices": ["이미지", "볼륨", "포트", "브랜치"],
      "answer": 1,
      "hint": "붕어빵에 비유하면 '틀'에 해당합니다."
    }
  ],
  "best_score": 50,
  "best_detail": { "correct": 1, "total": 2 },
  "history": [
    { "played_at": "2026-08-01 15:13:53", "total": 2, "correct": 1, "score": 50 }
  ]
}
```

| 키 | 자료형 | 의미 |
|---|---|---|
| `quizzes` | `list` | 퀴즈 목록 |
| `quizzes[].question` | `str` | 문제 내용 |
| `quizzes[].choices` | `list[str]` | 선택지 **정확히 4개** |
| `quizzes[].answer` | `int` | 정답 번호 (1~4) |
| `quizzes[].hint` | `str` | 힌트 (없으면 빈 문자열) |
| `best_score` | `int` | 최고 점수 (0~100) |
| `best_detail` | `dict` | 최고 점수를 낸 판의 `correct`(맞힌 수) / `total`(푼 문제 수) |
| `history` | `list[dict]` | 게임 기록 최근 20개 (`played_at`, `total`, `correct`, `score`) |

### 브랜치 전략

과제 요구사항 6번에 따라 **퀴즈 풀기 기능을 별도 브랜치에서 개발**했습니다.

```bash
git checkout -b feature/play-quiz     # 작업용 브랜치 생성
# play.py 작성 + game.py 연결 수정
git commit -m "Feat: 퀴즈 풀기 기능 구현 ..."
git checkout main
git merge --no-ff feature/play-quiz   # 병합 기록이 남는 방식으로 합침
```

- 브랜치 작업 중 `main` 브랜치의 `game.py` 는 "퀴즈 풀기 준비 중" 상태로 유지되어,
  **개발 중인 코드가 안정 버전에 영향을 주지 않음**을 확인했습니다.
- `--no-ff` 를 사용한 이유: 기본 병합은 이력을 일직선으로 만들어 **브랜치를 쓴 흔적이 사라집니다.**
  `--no-ff` 는 병합 커밋을 남겨 작업 이력을 보존합니다.
