# 미션2 — 나만의 퀴즈 게임

터미널에서 동작하는 파이썬 콘솔 퀴즈 게임입니다.
Python 기본 문법 + 클래스(객체 지향) + JSON 파일 저장으로 만들었고,
**프로그램을 껐다 켜도 추가한 퀴즈와 최고 점수가 그대로 유지**됩니다.

- **저장소**: https://github.com/Quartz13177/mission2
- 외부 라이브러리 없이 **표준 라이브러리만** 사용 (`json`, `os`, `random`, `datetime`)

### 저장소 접근 안내

이 저장소는 **Public** 으로 공개되어 있어 GitHub 로그인 없이 열람할 수 있습니다.


## 2) 퀴즈 주제와 선정 이유

**주제: 개발 입문 기초 상식** (터미널 · Docker · Git · Python · AI 연산)

입학연수 미션1~3에서 **직접 손으로 실습해 확인한 개념만** 문제로 만들었습니다.

| 문제 | 미션1에서 직접 확인한 장면 |
|---|---|
| 컨테이너 설계도 역할은? → 이미지 | `docker images` 와 `docker ps` 의 차이 |
| 현재 위치 확인 명령어는? → `pwd` | 터미널 실습에서 가장 먼저 친 명령 |
| 권한 755에서 소유자 권한은? → 읽기+쓰기+실행 | `permission denied` → `chmod 755` → 실행 성공 |
| 컨테이너 삭제 후 데이터를 남기려면? → 볼륨 | 볼륨은 유지 / 컨테이너 내부는 소실되는 대조 실험 |
| localhost:8080 접속을 가능하게 하는 것은? → 포트 매핑 | `-p 8080:80` 으로 브라우저 접속 확인 |

**선정 이유**

1. 정답의 근거를 **제가 직접 설명할 수 있는** 문제들입니다. 남의 상식 퀴즈가 아닙니다.
2. 같은 과정을 듣는 동료에게 **그대로 복습 도구**로 건넬 수 있어 프로그램의 쓸모가 분명합니다.
3. 미션1~3을 관통하는 개념을 문제로 정리하면서 스스로 복습이 되었습니다.

> 기본 퀴즈는 `default_data.py` 의 `RAW_QUIZZES` 목록에 정의되어 있습니다.
> 문항을 늘리거나 주제를 바꾸려면 이 목록만 수정하면 되며, 다른 파일은 손댈 필요가 없습니다.

## 5) 기능 목록

| 번호 | 기능 | 설명 |
|---|---|---|
| 1 | **퀴즈 풀기** | 풀 문제 수를 정하고 출제 → 정답/오답 즉시 안내 → 결과 점수 표시. `h` 입력 시 힌트(−5점) |
| 2 | **퀴즈 추가** | 문제·선택지 4개·정답 번호·힌트를 입력받아 등록하고 즉시 저장 |
| 3 | **퀴즈 목록** | 등록된 문제 목록 표시 (정답은 감춤, 힌트 보유 문제는 💡 표시) |
| 4 | **점수 확인** | 최고 점수와 상세(N문제 중 M개 정답), 최근 5회 기록 |
| 5 | **퀴즈 삭제** | 번호를 선택해 삭제 (삭제 전 y/n 확인) |
| 6 | **종료** | 저장 후 종료 |

### 점수 계산식

```
점수 = round(100 × 맞힌 개수 ÷ 푼 문제 수) − (힌트 사용 횟수 × 5)      # 최소 0점
```

예) 3문제 중 2문제 정답 + 힌트 1회 → `round(100 × 2 ÷ 3) − 5` = `67 − 5` = **62점**

## 6) 데이터 유지 확인 체크리스트

재실행 후에도 데이터가 남는지 **3분 안에 검증**할 수 있는 절차입니다.

| 단계 | 조작 | 기대 결과 |
|---|---|---|
| 1 | `python main.py` 실행 | `📂 저장된 데이터가 없어 기본 퀴즈로 시작합니다.` (첫 실행 시) |
| 2 | `2` → 새 퀴즈 1개 추가 | `✅ 퀴즈가 추가되었습니다! (현재 총 9개)` |
| 3 | `3` → 목록 확인 | `[9]` 번에 방금 추가한 문제가 보임 |
| 4 | `1` → 퀴즈 풀기 → 종료까지 | `🏆 결과: …점` 표시 |
| 5 | `6` → 종료 | `💾 데이터를 저장하고 종료합니다.` |
| 6 | `python main.py` **다시 실행** | `📂 저장된 데이터를 불러왔습니다. (퀴즈 9개, 최고점수 N점)` ← **핵심** |
| 7 | `3` → 목록 확인 | 추가한 `[9]` 번 문제가 **그대로 존재** |
| 8 | `4` → 점수 확인 | 최고 점수와 **최근 기록의 날짜·시각**이 남아 있음 |

**실제 검증 결과 (3회 연속 실행)**

```text
[1회차] 퀴즈 추가 → [9] 제가 미션1에서 사용한 컨테이너 실행 앱은?
        ↓ 프로그램 완전 종료 ↓
[2회차] 📂 저장된 데이터를 불러왔습니다. (퀴즈 9개, 최고점수 0점)
        ↓ 퀴즈 풀고 종료 ↓
[3회차] 🏆 최고 점수: 50점 (2문제 중 1문제 정답)
        🕘 2026-08-01 15:13:53 | 2문제 중 1개 정답 | 50점
```

> 💡 파일 상태를 직접 보고 싶다면 `state.json` 을 텍스트 편집기로 열면 됩니다.
> 사람이 읽을 수 있는 형식이라 저장 결과를 눈으로 확인할 수 있습니다.

```
├── storage.py         # Storage 클래스 — state.json 저장·불러오기 (창고 관리인)
├── ui.py              # 입력 검증 / 출력 도우미 함수
├── config.py          # 설정 값 (파일 경로, 선택지 수, 랜덤 여부, 힌트 감점)
```

## 9) 모듈 간 호출 계약

**누가 누구를 부르는지**와 **주고받는 값**을 정리했습니다.

```
main.py
  └─ QuizGame().run()
        ├─ Storage.load()            → dict(quizzes, best_score, best_detail, history, notes)
        ├─ ui.ask_int()              → int (메뉴 번호)
        ├─ play.run_round(self)      → None (결과는 콜백으로 전달)
        │     ├─ ui.ask_int/ask_choice()   → int | "h"
        │     ├─ Quiz.render() / is_correct() / answer_text()
        │     └─ game.record_result(correct, total, hints)   ← 되돌려 호출
        └─ Storage.save(...)         → bool
```

| 호출자 → 피호출자 | 넘기는 값 | 돌려받는 값 | 계약 |
|---|---|---|---|
| `main` → `QuizGame.run()` | 없음 | 없음 | 프로그램 종료 시까지 반환하지 않음 |
| `QuizGame` → `Storage.load()` | 없음 | `dict` (5개 키) | **어떤 오류에도 예외를 던지지 않음.** 실패 시 기본값 + `notes` 메시지 |
| `QuizGame` → `Storage.save()` | 퀴즈 목록, 점수, 상세, 기록 | `bool` | 실패해도 예외 없이 `False` 반환 + 경고 출력 |
| `QuizGame` → `play.run_round()` | `QuizGame` 객체 자신 | 없음 | 결과는 `game.record_result()` 로 되돌려 전달 |
| `play` → `Quiz.is_correct()` | 사용자 입력 번호 | `bool` | 채점 책임은 `Quiz` 가 가짐 |
| 모든 모듈 → `ui.*` | 안내문·허용 범위 | 검증 통과한 값 | **검증에 실패한 값은 절대 반환하지 않음** |

> 이 계약 덕분에 `game.py` 는 "입력이 올바른지" 를 다시 검사하지 않아도 됩니다.
> `ui` 를 통과한 값은 이미 유효하다는 것이 보장되기 때문입니다.

### 10-1. 스키마 요약 (필드 / 타입 / 제약)

| `best_score` | `int` | ❌ | **0 이상**. 음수·문자열이면 0 | 0 으로 보정 |
| `best_detail` | `dict` | ❌ | `correct`, `total` 모두 0 이상 정수 | 0 으로 보정 |
| `best_detail.correct` | `int` | ❌ | 0 이상 | 0 으로 보정 |
| `best_detail.total` | `int` | ❌ | 0 이상 | 0 으로 보정 |
| `history` | `list[dict]` | ❌ | 항목에 `score` 키가 있어야 인정. **최근 20개만 보관** | 조건 미달 항목 제외 |
| `history[].played_at` | `str` | ❌ | `"YYYY-MM-DD HH:MM:SS"` | 없으면 `-` 로 표시 |
| `history[].total` / `.correct` / `.score` | `int` | ❌ | — | 없으면 0 |

**핵심 제약은 `Quiz.__init__` 에서 강제**되므로, 일단 만들어진 `Quiz` 객체는 항상 유효합니다.

```python
if len(choices) != CHOICE_COUNT:
    raise ValueError("선택지는 정확히 %d개여야 합니다." % CHOICE_COUNT)
if answer < 1 or answer > CHOICE_COUNT:
    raise ValueError("정답 번호는 1~%d 사이여야 합니다." % CHOICE_COUNT)
```

## 11) 왜 JSON을 선택했는가

| 장점 | 설명 | 이 프로젝트에서의 의미 |
|---|---|---|
| **사람이 읽을 수 있음** | 메모장으로 열어도 구조가 그대로 보임 | 저장 결과를 눈으로 검증 가능, 디버깅이 쉬움 |
| **경량성** | 태그·스키마 선언 등 부가 정보가 없어 **데이터 대비 용량이 작음** | 퀴즈 8개 = **2.1KB**. 별도 DB 서버·드라이버 없이 파일 하나로 끝 |
| **교환성(상호운용성)** | 언어·플랫폼에 관계없이 표준으로 지원 | 나중에 웹/모바일로 확장해도 **같은 파일을 그대로** 읽을 수 있음 |
| **표준 라이브러리 지원** | 파이썬 `json` 모듈만으로 처리 | 과제 조건인 "외부 라이브러리 금지"를 만족 |
| **자료구조와 1:1 대응** | `dict` ↔ object, `list` ↔ array | 변환 코드가 단순해져 버그 여지가 줄어듦 |

### 다른 형식과 비교

| 형식 | 용량 | 사람이 읽기 | 이 과제에 적합한가 |
|---|---|---|---|
| **JSON** | 작음 | 쉬움 | ✅ 채택 |
| XML | 큼 (닫는 태그 중복) | 보통 | 불필요하게 무겁다 |
| CSV | 가장 작음 | 쉬움 | ❌ **중첩 구조(선택지 4개 배열)를 표현하기 어렵다** |
| 파이썬 `pickle` | 작음 | **불가** (이진) | ❌ 다른 언어에서 못 읽고, 내용 확인이 안 된다 |
| SQLite | 중간 | 불가 (전용 도구 필요) | 데이터가 커지면 유리 → [15절](#15-확장성-검토--퀴즈가-1000개가-되면) 참고 |

> **한 줄 요약**: 지금 규모(수십~수백 문항)에서는 **가볍고, 읽기 쉽고, 어디서든 열 수 있는** JSON 이 최적입니다.

## 12) 저장 / 불러오기 흐름도

### 불러오기 (`Storage.load()`)

```
프로그램 시작
    ↓
state.json 이 있는가? ──── 없음 ──→ 기본 퀴즈 8개 + 안내 메시지
    ↓ 있음
JSON 파싱 성공? ────── 실패 ──→ 손상 파일을 state.json.bak 으로 이동
    ↓ 성공                        → 기본 퀴즈 + 안내 메시지
최상위가 dict 인가? ── 아니오 ─→ 위와 동일 처리
    ↓ 예
퀴즈 항목을 하나씩 Quiz 로 복원
    ├─ 성공 → 목록에 추가
    └─ 실패 → 그 항목만 건너뛰고 개수를 세어 안내
    ↓
살아남은 퀴즈가 0개? ── 예 ──→ 기본 퀴즈로 대체
    ↓ 아니오
best_score / best_detail / history 값 보정 (음수·타입 오류 → 0)
    ↓
QuizGame 속성에 반영 + notes 메시지 출력
```

### 저장하기 (`Storage.save()`)

```
현재 상태(퀴즈·점수·기록)
    ↓
Quiz 객체 → to_dict() 로 변환
    ↓
state.json.tmp 에 먼저 기록          ← ① 원본은 아직 그대로
    ↓
os.replace(tmp → state.json)         ← ② 마지막 순간에 교체 (원자적)
    ↓
성공 True / 실패 False + 경고 출력
```

> **왜 임시 파일을 거치는가**: 원본에 직접 쓰다가 중간에 프로그램이 멈추면
> **반쯤 쓰인 파일**이 남아 데이터 전체를 잃습니다. 임시 파일에 쓰다 멈추면 원본은 멀쩡합니다.
> `os.replace()` 는 운영체제가 보장하는 원자적 연산이라 "교체 중간 상태"가 존재하지 않습니다.

## 13) 예외 처리와 복구 시나리오

### 13-1. 처리하는 예외

| 상황 | 잡는 예외 | 프로그램 동작 |

### 13-2. 운영자(사용자) 안내 문구와 조치

| 화면에 나오는 메시지 | 의미 | 사용자가 할 일 |
|---|---|---|
| `📂 저장된 데이터가 없어 기본 퀴즈로 시작합니다.` | 첫 실행 (정상) | 없음. 종료 시 파일이 생성됩니다 |
| `📂 데이터 파일이 손상되어 기본 퀴즈로 복구했습니다. (손상 파일: state.json.bak)` | JSON 이 깨짐 | `state.json.bak` 을 열어 살릴 내용이 있는지 확인. 없으면 삭제 |
| `📂 형식이 잘못된 퀴즈 N개를 건너뛰었습니다.` | 일부 문항만 깨짐 | 목록에서 누락된 문항을 다시 추가 |
| `⚠️  저장에 실패했습니다. (…)` | 디스크 가득참·권한 없음 | 디스크 여유 공간·폴더 쓰기 권한 확인 후 재시도 |
| `⚠️  퀴즈는 추가되었지만 파일 저장에 실패했습니다.` | 메모리에는 있으나 파일에 못 씀 | **종료 전에** 원인을 해결하고 다시 시도 (종료하면 유실) |

### 13-3. 손상 복구 실제 검증

```text
# state.json 을 일부러 깨뜨린 뒤 실행
$ echo '{ "quizzes": [ 이건깨진JSON' > state.json
$ python main.py

📂 데이터 파일이 손상되어 기본 퀴즈로 복구했습니다. (손상 파일: state.json.bak)
   → 퀴즈 8개로 정상 실행됨

$ ls state.json.bak
state.json.bak      ← 손상된 원본이 삭제되지 않고 보관됨
```

> 자동 복구가 데이터를 조용히 없애면 안 됩니다.

## 14) 자원 정리 (종료 훅)

현재 프로그램은 **파일을 `with open(...)` 블록 안에서만 열고 즉시 닫으므로**,
프로그램 종료 시 별도로 닫아야 할 자원이 없습니다.

```python
with open(self.path, "r", encoding=ENCODING) as file:
    raw = json.load(file)
# 블록을 벗어나는 순간 자동으로 닫힘 (오류가 나도 보장됨)
```

다만 기능이 확장되어 **지속적으로 열려 있는 자원**이 생기면 정리 지점이 필요합니다.

| 추가될 수 있는 자원 | 필요한 정리 | 정리 위치 |
|---|---|---|
| DB 연결 (SQLite 등) | `conn.close()` | `QuizGame.run()` 의 종료 분기 + `except` 블록 |
| 네트워크 세션 | `session.close()` | 위와 동일 |
| 로그 파일 핸들 | `logfile.close()` | 위와 동일 |
| 백그라운드 스레드 | `thread.join()` / 종료 플래그 | 위와 동일 |

**권장 구현 위치** — 종료 경로가 두 군데뿐이므로 여기에 `cleanup()` 을 추가하면 충분합니다.

```python
def cleanup(self):
    """종료 직전에 열려 있는 자원을 정리한다. (현재는 정리 대상 없음)"""
    pass

# game.py 의 run() 안
else:                      # 메뉴 6번 종료
    self.save()
    self.cleanup()         # ← 정상 종료 경로
    break
except (KeyboardInterrupt, EOFError):
    self.save()
    self.cleanup()         # ← 강제 중단 경로
    break
```

> 파이썬에는 `try/finally` 나 `atexit` 모듈도 있지만,
> **종료 경로가 명확하게 두 곳뿐**인 이 구조에서는 명시적 호출이 더 읽기 쉽습니다.

## 15) 확장성 검토 — 퀴즈가 1000개가 되면?

현재 구조는 **파일 전체를 한 번에 읽고 한 번에 쓰는(all-in-memory)** 방식입니다.
데이터가 커질 때 무엇이 문제가 되는지 **실제로 측정**했습니다.

### 15-1. 실측 결과

> 측정 환경: Windows 11 / Python 3.12.10 / `Storage.load()` · `save()` 호출 구간, `tracemalloc` 으로 메모리 측정

| 퀴즈 수 | 파일 크기 | 불러오기 | 저장 | 메모리 사용 |
|---|---|---|---|---|
| **8개** (현재) | 2.1 KB | 13.8 ms | 2.9 ms | 18 KB |
| 100개 | 25.5 KB | 29.6 ms | 4.4 ms | 117 KB |
| **1,000개** | 259.2 KB | **53.0 ms** | **12.7 ms** | **1.1 MB** |
| 10,000개 | 2,649.9 KB | 170.3 ms | 115.5 ms | 11.5 MB |

### 15-2. 해석 — 무엇이 진짜 문제인가

1. **1,000개까지는 성능이 문제가 되지 않습니다.**
   시작 시 53ms, 저장 12.7ms 로 사람이 체감할 수 없는 수준입니다. 메모리도 1.1MB 에 불과합니다.
2. 데이터 양과 시간이 **거의 정비례(O(N))** 합니다. 8→10,000개(1250배)에서 불러오기 12배,
   저장 40배로, 파일 크기 증가에 따른 선형 증가 경향을 보입니다.
3. **진짜 병목은 속도가 아니라 "매번 전체를 다시 쓰는" 구조입니다.**
   퀴즈를 1개 추가·삭제할 때마다 **1,000개 전부를 직렬화해 파일에 다시 씁니다.**
   10,000개에서는 한 문항 추가에 115ms 가 들며, 이 비용은 계속 커집니다.
4. **검색 기능이 없다는 것이 더 큰 문제입니다.**
   `list_quizzes()` 는 전체를 한 줄씩 출력하므로 1,000개면 **터미널에 1,000줄**이 쏟아집니다.
   원하는 문제를 찾을 방법이 사실상 없습니다.
5. **동시 접근을 고려하지 않았습니다.** 두 개의 프로그램이 동시에 실행되면
   나중에 저장한 쪽이 앞선 변경을 덮어씁니다. (현재는 1인 사용 전제)
6. 메모리는 **퀴즈 1개당 약 1.1KB** 를 사용합니다.
   10만 개라도 약 115MB 로 일반 PC에서 감당 가능하지만, 그 전에 3·4번 문제가 먼저 발생합니다.

### 15-3. 규모별 대응 방안

| 규모 | 예상 증상 | 권장 대응 |
|---|---|---|
| ~200개 | 없음 | **현재 구조 유지** |
| 200~1,000개 | 목록 출력이 길어 찾기 어려움 | **페이지 나눔**(20개씩), **검색·태그 필터** 추가 |
| 1,000~10,000개 | 추가·삭제마다 전체 재저장 부담 | **변경분만 기록**(append-only 로그) 또는 **주기적 일괄 저장** |
| 10,000개~ | 시작 지연·메모리 부담·동시성 문제 | **SQLite 전환** (표준 라이브러리 `sqlite3` 로 외부 의존성 없음) |

### 15-4. SQLite 전환 시 얻는 것

| 항목 | 현재 (JSON) | SQLite 전환 후 |
|---|---|---|
| 문항 1개 추가 | 전체 파일 재작성 | 해당 **행 1개만** 삽입 |
| 검색 | 전체 반복 비교 | **인덱스** 기반 조회 |
| 시작 시 로딩 | 전체를 메모리에 적재 | **필요한 만큼만** 조회 |
| 동시 접근 | 나중 저장이 덮어씀 | 트랜잭션·잠금으로 보호 |
| 사람이 읽기 | ✅ 쉬움 | ❌ 전용 도구 필요 |

### 15-5. 전환이 쉬운 이유 — 이미 분리해 두었기 때문

```
현재:  QuizGame ──→ Storage ──→ state.json
전환:  QuizGame ──→ Storage ──→ quiz.db   ← Storage 내부만 교체
                      ↑
              load() / save() 인터페이스는 그대로
```

`QuizGame` 은 파일을 직접 다루지 않고 **`Storage.load()` / `save()` 만 호출**합니다.
따라서 저장 방식을 바꿔도 **`storage.py` 한 파일만 수정**하면 되고,
게임 로직(`game.py`, `play.py`)과 데이터 정의(`quiz.py`)는 손댈 필요가 없습니다.

> 이것이 [9절 모듈 간 호출 계약](#9-모듈-간-호출-계약)을 명시해 둔 실질적인 이유입니다.

## 16) 백업 정책

`state.json` 은 사용자가 직접 만든 퀴즈와 점수 기록이 담긴 **유일한 원본**입니다.

### 16-1. 프로그램이 자동으로 하는 것

| 보호 장치 | 막아 주는 상황 |
|---|---|
| 임시 파일 → 교체 방식 저장 | 저장 도중 중단으로 인한 **파일 손상** |
| 손상 파일 `.bak` 보관 | 자동 복구 과정에서의 **데이터 소실** |
| 항목별 건너뛰기 | 일부 문항 오류로 **전체를 잃는 것** |

**그러나 파일 자체가 삭제되거나 디스크가 고장 나는 경우는 막지 못합니다.**

### 16-2. 권장 백업 절차

```bash
# 수동 백업 (날짜를 붙여 덮어쓰기 방지)
cp state.json backups/state-$(date +%Y%m%d).json          # macOS / Linux
Copy-Item state.json "backups\state-$(Get-Date -f yyyyMMdd).json"   # Windows

# 복구
cp backups/state-20260801.json state.json
```

### 16-3. 권장 주기

| 사용 형태 | 주기 | 보관 |
|---|---|---|
| 학습·개인 사용 | 문항을 크게 추가한 날 | 최근 3개 |
| 수업 자료로 공유 | 주 1회 + 배포 직전 | 최근 4주 |
| 여러 명이 사용 | 매일 자동 + **원격 동기화** | 일 7 / 주 4 |

### 16-4. 원격 동기화 방안

| 방법 | 장점 | 주의 |
|---|---|---|
| 클라우드 폴더(OneDrive·iCloud) | 설정만 하면 자동 | 동시 편집 시 충돌 파일 생성 가능 |
| 별도 **비공개** Git 저장소 | 변경 이력까지 보존 | **현재 저장소는 Public 이므로 절대 커밋 금지** |
| 외장 디스크 정기 복사 | 오프라인 보관 | 수동이라 잊기 쉬움 |

> ⚠️ `state.json` 은 `.gitignore` 로 제외되어 있습니다.
> 백업 목적이라도 **공개 저장소에는 커밋하지 마세요.** 개인 학습 기록이 그대로 공개됩니다.

### 18-3. 커밋 단위 기준

**"한 문장으로 설명되는 하나의 완결된 변경"** 을 1커밋으로 잡았습니다.
이 프로젝트에서는 대체로 **파일 1개 = 기능 1개 = 커밋 1개** 가 되었습니다.

| 판단 | 예시 |
|---|---|
| ✅ 적절 | `ui.py` 입력 검증 유틸 완성 (102줄, 파일 1개) |
| ✅ 적절 | `play.py` 신규 + `game.py` 연결 수정 (**한 기능을 위해 두 파일이 함께 바뀜**) |
| ❌ 너무 큼 | 클래스 3개 + README 를 한 번에 커밋 → 되돌릴 때 원하는 것만 못 고름 |
| ❌ 너무 작음 | 오타 1글자마다 커밋 → 이력이 지저분해져 읽을 수 없음 |

> **기준**: *"이 커밋만 되돌렸을 때 말이 되는가?"* 가 되면 적절한 단위입니다.

| CI 자동 검사 | 테스트·문법 검사를 자동 수행 |
| Merge 후 브랜치 삭제 | 저장소를 깔끔하게 유지 |

## 20) 요구 변경 시 영향 범위 체크리스트

기능을 수정할 때 **어느 파일을 봐야 하는지** 미리 정리했습니다.

| 바꾸고 싶은 것 | 수정할 파일 | 함께 확인할 것 |
|---|---|---|
| 선택지를 4개 → 5개로 | `config.CHOICE_COUNT` | `state.json` 기존 데이터가 4개짜리라 **로드 시 전부 실패** → 마이그레이션 필요 |
| 점수 계산식 | `game._calculate_score()` | 저장된 `best_score` 와 기준이 달라짐 (기존 기록 해석 주의) |
| 힌트 감점 폭 | `config.HINT_PENALTY` | 없음 (즉시 반영) |
| 문제 순서 랜덤 on/off | `config.SHUFFLE_QUESTIONS` | 없음 |
| 저장 위치·파일명 | `config.DATA_FILE` | `.gitignore` 항목도 함께 수정 |
| **저장 방식(JSON→DB)** | `storage.py` **만** | `load()`/`save()` **반환 형식 유지** 필수 ([9절 계약](#9-모듈-간-호출-계약)) |
| 메뉴 항목 추가 | `game.MENU_ITEMS`, `game.MENU_MAX`, `run()` 분기 | `ask_int` 범위(`MENU_MAX`)를 함께 수정하지 않으면 새 항목 선택 불가 |
| 출제 방식 변경 | `play.py` | `game.record_result()` 호출 규약 유지 |
| 입력 검증 규칙 | `ui.py` | 모든 메뉴에 동시에 영향 |
| 기본 퀴즈 내용·개수 | `default_data.RAW_QUIZZES` | 기존 `state.json` 이 있으면 **반영되지 않음**(파일 우선) |

### 자주 하는 실수

| 실수 | 증상 | 예방 |
|---|---|---|
| 메뉴 추가 시 `MENU_MAX` 미수정 | 새 메뉴를 골라도 "범위 밖" 경고 | 메뉴 관련 상수를 한 곳(`game.py` 상단)에 모아 둠 |
| `CHOICE_COUNT` 변경 후 기존 파일 유지 | 모든 퀴즈가 "형식 오류"로 건너뛰어짐 | 변경 전 `state.json` 백업 → 변환 |
| `Storage.load()` 반환 키 변경 | `QuizGame.load()` 에서 `KeyError` | 반환 형식을 계약으로 고정 (9절) |

## 21) 설계 판단 — 왜 클래스로 나눴는가

### 함수만 사용했다면

```python
quizzes = []          # 전역 변수로 상태 관리
best_score = 0
def play(): global quizzes, best_score ...
```

- 상태가 **전역 변수**로 흩어져, 어느 함수가 무엇을 바꾸는지 추적이 어렵습니다.
- 테스트할 때 전역 상태를 매번 초기화해야 합니다.

### 클래스로 나눈 결과

| 장점 | 이 프로젝트에서의 구체적 효과 |
|---|---|
| **상태와 동작을 함께 보관** | `QuizGame` 객체 하나가 퀴즈·점수·기록을 모두 들고 있어, 전역 변수가 없습니다 |
| **테스트 용이** | `QuizGame(storage=가짜Storage())` 처럼 **저장소를 갈아끼워** 파일 없이 테스트할 수 있습니다 |
| **재사용** | `Quiz` 는 게임과 무관하게 문제 데이터만 다루므로, 웹 버전에서도 그대로 재사용 가능합니다 |
| **변경 영향 최소화** | 저장 방식을 바꿔도 `storage.py` 만 수정하면 됩니다 |
| **책임이 이름에 드러남** | `Quiz`(문제) / `Storage`(파일) / `QuizGame`(진행) — 어디를 고칠지 이름만 봐도 알 수 있습니다 |

> `QuizGame.__init__(self, storage=None)` 이 `storage` 를 **밖에서 주입받을 수 있게** 설계된 이유가
> 위의 "테스트 용이" 항목입니다. 실제 테스트에서는 임시 경로를 쓰는 `Storage('bench.json')` 를 넣어
> 원본 데이터를 건드리지 않고 성능을 측정했습니다. ([15절 실측](#15-확장성-검토--퀴즈가-1000개가-되면))
